## 1. Bug root cause（64-bit exact_roots 性能退化）

两类互补退化（均在特定系数结构、高次因子上出现，与 degree 本身无关）：
1. **D0D3 型**：`Poly.intervals(0,1)` 对**无根**高次因子（deg 75–87）全量隔离退化（>120 s/pair）；`count_roots`（Sturm）对该类快（0.5 s）。
2. **Rnew 型**：`count_roots` / `sp.sturm` / `dup_sturm` 的 Sturm 链系数爆炸（deg-77 因子 63–82 s）；`Poly.intervals` 对该类快（0.01 s）。
3. 附加退化：`intervals(eps=…)` 细化对部分有根因子卡死（>60 s）；整体多项式上 intervals 返回嵌套端点区间导致窄化误判。

## 2. Fix（性能重构，语义不变）

1. **因子级处理**：sqf_list 分解后逐因子判定（避免整体 poly 全量隔离）。
2. **子进程双方法 early-exit**：`_factor_has_root_subprocess` 先 intervals、超时（10 s）换 count_roots（两方法互补；科学判定始终 exact——子进程超时仅为性能保护）。
3. **有根因子窄化**：`_narrow_box` = numpy 浮点**仅定位候选** + 一次窄区间 `intervals(v±δ)`（exact）→ 精确窄区间；覆盖不足时回退精确二分 `_refine_box`。
4. 修复 `_narrow_box` 端点退化区间误计（嵌套区间 (0,0)/(0,1)/(1,1) 时 total 只计非退化）。
5. `materialize_root=False` 全程不物化 RootOf；float 仅定位/展示。

### 8 个关键问题回答
1. **ranking robustness 是否 width-dependent**：是。ER 从 16 全稳 → 32 出现 D2 翻转 → 64 基本回稳（仅 D2=1）；MED 从 16 广泛敏感 → 32/64 高度集中。
2. **metric dependence**：全程显著（ER 远稳于 MED；32-bit 例外：ER D2 翻转 11 对）。
3. **path dependence**：持续存在（D2/Rnew 是敏感路径；D4/D5 全 width 稳定——除 16-bit MED 外）。
4. **stable-regime topology**：随 width 重构（16 位 71 区间 → 32/64 约 33–35）。
5. **multi-flip/tie**：随 width 出现并增多（32 位 1 → 64 位 10，全在随机路径）；endpoint tie 32→64 增多（err_0 设计族）。
6. **nominal-best**：各 width 各路径内 best 设计保持稳定（无 path 内切换；32/64 的 best 设计族与 16 不同——见 family JSON regimes 首组）。
7. **exact pipeline 扩展**：16→32→64 全部正常完成（1396/1396）；64 位需性能修复（三类退化），修复后稳定。
8. **scaling**：poly degree 2×/width（32→64→96）、NNF ~1.4–5×（75KB→220KB→1.16MB）、family runtime 秒级–3.4 min（Rnew MED）。
